## They aren't alternatives, they're layers

- **Dataset** — the substrate. Schema, grain, provenance, freshness, trust.
- **Analytics** — the derivation. Aggregation, statistics, inference, modeling.
- **Visualization** — the encoding. Data made visible.

## Visualization is two jobs

This is the core of the piece.

### Exploratory — before analytics

Histograms, missingness maps, scatter matrices, value counts. Ugly, fast,
disposable. Made **for you**. It answers: *what is this data, actually?*

TODO: Concrete catches — the duplicated join that doubled a row count, the

These are found by looking, not by asserting.

### Explanatory — after analytics

The polished chart in the report. Made **for others**. It answers:
*here is the conclusion, and here is why you should believe it.*

analyst's speed, explanatory optimizes for the reader's comprehension.
Using one where you need the other is a real and common mistake.

## The actual order

```
Dataset → exploratory viz → Analytics → explanatory viz
```

## Why the order gets inverted

Attention flows to the visible layer. Dashboards are demoable; fixing the
grain of a fact table is not.

TODO: The sharpest version of the argument — visualization raises *confidence*
faster than it raises *correctness*. A polished chart on an untrusted dataset
launders bad data into a confident decision. That makes it worse than no chart.
